## 3. Gaps Identified That Require Sol / Opus / Backend Implementation

1. **Public Landing (`apps/web/app/page.tsx`):** Needs Sol to replace the 34-line static block with the approved 5-section landing layout and `200ms` intent prefetch on `Start simulation`.
2. **Centered Incoming Call & Morphing Dana Panel (`apps/web/app/night/night-run.tsx` & `world.css`):** Needs Sol/Opus to switch the `paged` call state from a top-aligned `.call-layout` / right-docked `440px` sidebar (`data-layout="side"`) to the centered `480px` alert card (`data-layout="center"`), and add the explicit `Answer by Text` vs. `Answer with Voice (Mic Consent)` split.
3. **Night Board Primary `p95_ms` Trend Card (`apps/web/app/night/incident-board.tsx`):** `metrics.p95_ms` is already returned by the backend and fixture state (`380 ms -> 1450 ms -> 390 ms`), but `incident-board.tsx` currently only renders 2 primary SVG trend cards (`Checkout error rate` and `Successful orders`). Sol should add the 3rd primary SVG trend card for `p95 checkout latency` (`380 ms` baseline, `1,450 ms` peak, `390 ms` post-rollback).
4. **Dedicated Morning Meeting Component (`apps/web/app/morning/morning-meeting.tsx` & `morning-world.tsx`):** Currently `morning-world.tsx` renders an empty placeholder (`Opened: briefing`) in fixture mode and scrolls `<MorningWorkspace>` in API mode. Sol and Opus should mount the shared 3-beat `MorningMeeting` view that drives both the in-room projector canvas (`office_project_screen_plane`) and the HTML meeting panel across all 7 state matrix modes.
